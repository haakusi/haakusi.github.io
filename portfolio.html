CASE 01

A developer portal that behaves like a product system

AWARD · PRODUCTIZING
Context

Product APIs, SDK behavior, execution environments, and support knowledge were fragmented. A developer's first successful call depended too much on local setup and expert help.

제품 API, SDK 동작, 실행 환경과 지원 지식이 분절돼 있었습니다. 개발자가 첫 호출에 성공하려면 로컬 설정과 전문가 지원에 과도하게 의존해야 했습니다.

My decision

Build six connected surfaces—not another documentation site. Docs, an API source of truth, a device emulator, MCP tools, a Linux/AWS sandbox, and evaluation gates share one operation model.

문서 사이트를 하나 더 만드는 대신 여섯 개의 제품 표면을 연결했습니다. 문서, API 단일 기준, 장치 에뮬레이터, MCP 도구, Linux/AWS 샌드박스와 평가 게이트가 같은 operation model을 참조합니다.

Natural-language verification

Through MCP, developers can recall complex user, door, authentication, and event scenario history in natural language, replay it inside the Linux/AWS sandbox, and verify it immediately. The same gateway is designed to extend from the emulator to physical devices.

MCP로 사용자·도어·인증·이벤트의 복합 시나리오 이력을 자연어로 호출하고 Linux/AWS 샌드박스에서 재실행해 즉시 검증합니다. 같은 게이트웨이를 에뮬레이터에서 실제 장치까지 확장하도록 설계했습니다.

Current state

Selected as one of five finalist teams with KRW 3 million in development funding, then built solo in eight weeks with an AI-native workflow and won the company-wide excellence award with a KRW 10 million prize. It is now being hardened toward a September 2026 release target.

5개 팀 최종 선정으로 개발비 300만원을 받은 뒤 AI-native workflow로 1인 8주 동안 구축해 전사 우수상과 상금 1,000만원을 받았습니다. 현재 2026년 9월 목표 릴리스를 위해 보안·운영·지원 기준을 제품 수준으로 강화하고 있습니다.

01 Architecture & implementation One operation model across six product surfaces

The API source of truth feeds browser execution, SDK examples, the device emulator, MCP tools, and the Linux/AWS sandbox. Keeping these surfaces on one operation model prevents documentation, examples, and executable behavior from drifting apart.

API 단일 기준을 브라우저 실행, SDK 예제, 장치 에뮬레이터, MCP 도구와 Linux/AWS 샌드박스가 함께 사용합니다. 문서·예제·실행 동작이 서로 달라지지 않도록 하나의 operation model로 묶었습니다.

02 Developer workflow First API call to a replayable device scenario

A developer can call an API in the browser without Postman, reproduce the SDK workflow without a physical device, and then move the same user, door, authentication, and event scenario into a sandbox or real-device gateway.

Postman 없이 브라우저에서 API를 호출하고, 실제 장치 없이 SDK 흐름을 재현한 뒤, 같은 사용자·도어·인증·이벤트 시나리오를 샌드박스나 실제 장치 게이트웨이로 확장할 수 있게 구성했습니다.

03 Verification & troubleshooting Scenario history makes complex failures replayable

When a multi-step flow fails, MCP recalls the scenario history in natural language and replays it inside the sandbox. This separates setup errors, API-contract errors, device-state errors, and scenario errors before the workflow reaches a physical device.

여러 단계의 흐름이 실패하면 MCP가 시나리오 이력을 자연어로 호출해 샌드박스에서 재실행합니다. 실제 장치로 넘어가기 전에 설정 오류·API 계약 오류·장치 상태 오류·시나리오 오류를 구분할 수 있습니다.

CASE 02

AI-native modernization with meaning-preservation gates

2026.07—NOW · IN PROGRESS
Problem

About 200K LOC of Angular embedded in an iframe had evolved into a mixed Angular/React architecture with tangled routing, back navigation, and state boundaries.

iframe 안의 약 20만 LOC Angular가 Angular/React 혼합 구조로 발전하면서 routing, 뒤로가기와 상태 경계가 얽힌 기술 부채가 누적됐습니다.

Approach

I lead the frontend team with an AI-native migration harness that checks backend payloads and responses, API contracts, React behavior, useEffect, DOM, UI, CSS assertions, and E2E flows as separate release gates.

프론트팀을 리딩하며 backend payload/response, API contract, React 동작, useEffect, DOM, UI, CSS assertion과 E2E를 독립 릴리스 게이트로 다루는 AI-native migration harness를 설계했습니다.

PRINCIPLE

Generated code is not progress until equivalent behavior is proven.

IMPLEMENTATION MAP

How the rewrite preserves meaning

The stack is organized around migration boundaries and proof gates.

TypeScriptReactAngularPlaywrightREST APIDOM/UI/CSS/E2E
01 Migration boundary Route, state, and ownership before component conversion

The rewrite begins by separating routing, back navigation, and state ownership across the iframe boundary. React conversion follows only after each behavior has an explicit owner and a reproducible contract.

iframe 경계에 얽힌 라우팅·뒤로가기·상태 소유권을 먼저 분리합니다. 각 동작의 소유 주체와 재현 가능한 계약을 정한 뒤 React 전환을 진행합니다.

02 Verification harness Independent gates reveal different classes of regression

Backend payload and response, API contract, unit behavior, React and useEffect semantics, DOM structure, UI/CSS assertions, and E2E journeys fail independently. A green build therefore means more than generated code compiling.

Backend payload/response, API contract, unit 동작, React·useEffect 의미, DOM 구조, UI/CSS assertion과 E2E 여정을 독립적으로 실패하게 구성합니다. 따라서 빌드 성공은 생성 코드의 컴파일 이상을 의미합니다.

03 Verification & troubleshooting Diagnose routing, back navigation, and state ownership separately

When equivalent screens diverge, the team can identify whether the failure originated in the API contract, effect timing, DOM meaning, CSS state, or end-to-end navigation instead of treating the entire rewrite as one opaque regression.

동일 화면의 동작이 달라졌을 때 전체 전환을 하나의 불투명한 회귀로 보지 않고 API 계약·effect timing·DOM 의미·CSS 상태·E2E navigation 중 어디서 실패했는지 구분합니다.

CASE 03

Device-to-cloud engineering for physical access systems

FOUNDATION
Breadth with a purpose

My hardware experience is not a separate chapter. Radar, camera, FPGA, device packets, SDKs, biometric authentication, distributed events, servers, and web products taught me how physical failures travel through software boundaries.

하드웨어 경험은 별도 경력이 아닙니다. Radar, camera, FPGA, 장치 packet과 SDK, 생체인증, 분산 이벤트, 서버와 웹 제품을 다루며 물리 세계의 실패가 소프트웨어 경계를 어떻게 통과하는지 배웠습니다.

Sensor / packet SDK / capability Gateway / domain Server / event Web / cloud / agent
DIFFERENTIATOR

I can debug the device boundary and still design the developer abstraction above it.

Measured outcomes

Redesigned C++/Java WebSocket/Apache Ignite event processing for a 40%+ performance gain, reduced CPU processing by about 50% through a data-structure change, and shortened bulk deletion from the 30-second range to about three seconds.

C++·Java WebSocket·Apache Ignite 이벤트 처리를 재설계해 성능을 40%+ 개선하고, 자료구조 변경으로 CPU 처리를 약 50% 줄였으며, 대량 삭제를 30초대에서 약 3초로 단축했습니다.

01 Architecture & implementation Packet, capability, gateway, event, and web product

C++ device packets and capability state feed Java/Kotlin services and domain gateways for users, doors, authentication, and events. The same semantics then reach enterprise web products, installers, enrollment flows, and cloud integrations.

C++ 장치 패킷과 캐퍼빌리티 상태를 Java/Kotlin 서비스 및 사용자·도어·인증·이벤트 도메인 게이트웨이에 연결했습니다. 같은 의미가 엔터프라이즈 웹 제품·인스톨러·등록 흐름·클라우드 연동까지 이어집니다.

02 Platform decisions Routing, resilience, dynamic configuration, and distributed state

Spring Cloud Gateway replaced the unified Nginx gateway with URL and header routing, rate limiting, circuit breaking, TLS 1.2, and configuration updates without service restart. Apache Ignite and ZooKeeper supported distributed event and state coordination.

Spring Cloud Gateway로 Unified Nginx Gateway를 대체하며 URL·header routing, rate limiter, circuit breaker, TLS 1.2와 무중단 동적 설정 반영을 구현했습니다. Apache Ignite와 ZooKeeper로 분산 이벤트·상태 조정을 지원했습니다.

03 Verification & troubleshooting Measure the bottleneck before changing the abstraction

Distributed-event tracing led to a C++/Java WebSocket/Apache Ignite redesign with a 40%+ gain. Replacing a hot-path vector with a map reduced CPU processing by about 50%, while query and transaction changes shortened bulk deletion from the 30-second range to about three seconds.

분산 이벤트 추적으로 병목을 확인한 뒤 C++·Java WebSocket·Apache Ignite 흐름을 재설계해 40%+ 개선했습니다. hot path의 vector를 map으로 바꿔 CPU 처리를 약 50% 줄이고, query·transaction 변경으로 대량 삭제를 30초대에서 약 3초로 단축했습니다.

02 / OPERATING MODEL

Verification-first AI-native engineering

01

Define the real boundary

Start from the device, user, developer, or release failure—not from the model or framework.

02

Establish one source of truth

Make docs, APIs, tools, sandboxes, and tests share the same meaning before optimizing speed.

03

Design failure gates

Use unit, contract, DOM, UI, CSS, E2E, and evaluation layers so each type of wrong result fails visibly.

04

Turn a method into team leverage

Convert individual techniques into reusable harnesses, examples, and operating rules that other teams can adopt.
